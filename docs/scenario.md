# 场景底本：虚拟宇宙公司·官方客服（全课统一）

本文件是**全课的事实底本**。课里的 agent 人设、工具规则、记忆字段、工作流分支、知识库语料都从这里派生；
改场景必须**整条链一起改**：角色 → 任务 → 必须知道什么 → `workingMemory.schema` → 工具 → 政策语料。

## 一、设定

- **品牌**：虚拟宇宙公司 —— 卖**武器、装备与药剂**
- **渠道**：官方客服，客户在虚拟宇宙公司的直营渠道下单
- **货币**：**黑龙币**。商品是武器、装备与药剂，价格量级 399 – 24,999 黑龙币；客服的自主补偿上限是 50 黑龙币 —— 对 129 黑龙币的生命之水有意义，对 24,999 黑龙币的遁天梭只是零头，符合真实客服的授权量级
- **订单号是唯一凭证**：客服只要订单号，不要序列号；判定与记忆都以它为准
- **物流**：运输方「星际运输队」，状态形如「已签收（星际运输队抵达）」「运输中（已停留 5 天）」

## 二、产品与 SKU

| SKU | 价格 | 在课程里的作用 |
|---|---|---|
| 遁天梭 | 24,999 黑龙币 | 主体：换新、修复（收材料费） |
| 金丝网 | 1,299 黑龙币 | 配件：单独退换，用于判「装备本体还是配件」 |
| S 级飞刀 | 899 黑龙币 | 小额：让「≤ 50 黑龙币 自主补偿」有意义 |
| 生命之水 | 399 黑龙币 | 耗材：天然一条「易耗品不适用换新」的边界 |

**名词来源**：《吞噬星空》（我吃西红柿）—— 货币「黑龙币」、兵器「遁天梭 / 金丝网 / S 级飞刀」、消耗品「生命之水」、地点「地球·江南基地市」。本课程仅作个人学习用途；若要对外分享或公开仓库，按第九节名词表替换成中性词即可。

**约束**：不接任何真实平台 / 商家接口；所有订单都是本地 mock 数据，学员无需任何商家凭证。

## 三、售后政策（P1–P5）

条款必须**可判定**（时间窗口 + 条件 + 责任方），否则第 7 课的分支与第 11 课的判分都不成立。
措辞可以有星际味道，但**窗口天数、判定条件、责任方一个字都不能含糊**。

| 条款 | 内容 | 服务第几课 |
|---|---|---|
| **P1** | 签收后 **7 个自然日**内、原厂封禁未启：全额退款，星际运费商家承担 | 3（资格判定）、7（分支） |
| **P2** | 签收后 **15 个自然日**内出现质量问题（梭体灵纹闪烁、金丝断裂）：免费换新，需提供故障记录 | 3、11（判分） |
| **P3** | **1 年免费修复**：梭体核心非人为损坏免费修复；人为（含强行灌注念力）收材料费 | 3、9（到期提醒） |
| **P4** | 客服可自主补偿 **≤ 50 黑龙币**；超出需主管审批 | 8（审批有金钱后果） |
| **P5**（代码实现） | 耗材不适用 P3 修复（无维修价值）；退货与换新照常适用 | 3（工具分支） |
| **P6**（代码实现） | 未拆封但已过 7 天：无理由窗口关闭，不能退；有质量问题再按 P2 / P3 走 | 3（工具分支） |
| **P5** | 政策解释以本文件为准，客服不得口头加码 | 10（引用出处）、11（越权承诺） |

耗材（生命之水）与普通商品的区别只有一条：**不修复**（一次性消耗品无维修价值）—— 退货与换新照常适用。这样规则才自洽：若「能退不能换」，客户退了重买即可，限制形同虚设。

**两类问题分开答**（第 3 课的工具设计）：

- **政策类**（「生命之水能不能退」）→ 用 `listProducts` 的规则摘要回答，**不需要订单号**
- **个案类**（「我这单能不能退」）→ 客户不记得订单号就直接查订单（可按客户姓名或商品名筛）：`findOrders` 找到候选 → 向客户确认是哪一单 → 再调 `checkReturnEligibility`

## 四、客户问题五类（第 7 课的意图分类就用这五类）

1. **物流**：「运输队怎么停在半路了」
2. **换新**：「金丝断裂」
3. **故障**：「飞刀的刀刃崩口了」
4. **退货**：「不想要了，要退」
5. **不在售**：「我的机甲坏了」→ 直接说明无法受理，不再问订单号

## 五、mock 数据（学员项目内）

```text
src/mastra/data/products.ts 在售商品清单（名称 / 价格 / 类别 / repairable 是否可修复 / rule 规则摘要）
src/mastra/data/orders.ts   订单 + 客户 + 订单号 + 签收日期 + 物流 + 收货坐标
（第 10 课再加）              售后政策原文 —— 入库做 RAG 语料
```

数据要刻意覆盖全部分支（6 条，每类问题都有可演示的订单）。

**时间一律用「签收距今天数」而不是固定日期** —— 这样课程任何时候跑，判定结果都一样（用绝对日期的话，7 天 / 15 天窗口过几天就失效了）。

| 订单 | 场景 | 期望判定 |
|---|---|---|
| NX-1001 | 6 天前签收、封禁未启 | `refund`（P1） |
| NX-1002 | 13 天前签收、金丝断裂 | `exchange`（P2） |
| NX-1003 | 1 年 2 个月前签收（飞刀） | 超保修期，付费修复（P3 反面） |
| NX-1004 | 保修期内、飞刀故障 | `repair`（P3） |
| NX-1005 | 未签收、运输停留 5 天 | `pending` + 查物流（第 9 课） |
| NX-1006 | 签收 30 天、生命之水（耗材）有质量问题 | `reject`：已过 15 天换新窗口，耗材又不可修复 |
| NX-1007 | 签收 3 天、生命之水（耗材）封禁未启 | `refund`：耗材同样可退（走 P1） |

`address` 字段（收货坐标，如「地球·江南基地市 8 号住所」）留给第 13 课做 PII 脱敏。

**随便哪个订单号都能演练**：订单号匹配不到时，工具会退到示例订单（`NX-1002`）继续判定，并在返回的 `reason` 里注明「未匹配到该订单号，先按示例订单 NX-1002 演示」。真实项目里这里应该提示客户核对订单号 —— 教学时为了不卡住流程才这么兜底。

## 六、Agent 设定（第 2 课起逐课加行）

```text
你是虚拟宇宙公司官方客服。
- 职责：帮客户解决武器、装备与药剂的问题（退换、修复、运输）
- 客户说的商品含糊、或你不确定我们有没有这件商品时，调用 listProducts 查清单，再反问确认是哪一件
- 客户说的商品不在清单里，直接说明无法受理，不要再问订单号
- 客户只问某件商品的政策（能不能退 / 换 / 修）时，按 listProducts 的规则直接回答，不必查订单
- 要判具体订单时：客户不记得订单号，就问一句怎么称呼（或商品名），用 findOrders 查订单
- 查到候选订单后，先向客户确认「是 NX-1007 这一单吗」，确认无误再调 checkReturnEligibility
- 不要让客户去背订单号
- 客户说了「坏了 / 故障 / 不能用」就按质量问题判，说了「没拆封 / 不要了」就按未拆封判，不必反问
- 客户只给了订单号、没说问题类型时：按质量问题判，并在结论后补一句「若未拆封，也可按 P1 在 7 天内退货」，不要反问他
- 只承诺售后政策内的处置，政策外的一律说「需要主管确认」
- 中文、简短、专业，不卖萌
```

后续课按需追加（每加一行都对应一课、都可验收）：
第 3 课加「判定资格用工具」；第 4 课加「记住订单号/问题/已答复方案」；第 10 课加「引用条款编号」；第 13 课加「不索要、不回显敏感信息」。

## 七、闭环设计（为什么这些字段和工具不是装饰）

```text
orderId   记忆里存订单号  →  又是 checkReturnEligibility 的入参   →  「记下来」=「不用再问」
promise  记忆里存已答复的方案 →  后续轮次不许改口                →  客服最真实的诉求
issue    记忆里存问题类型  →  正是工具的第二个入参               →  模型只负责归类，规则交给代码
```

## 十、三条纪律（避免"夸张"吃掉严谨）

1. **规则零玩笑**：天数、条件、责任方、金额一律精确；俏皮只出现在商品名与话术里。
2. **术语固定**：装备（主体）/ 配件 / 耗材 三类分开，判定分支靠它们区分，不许混用。
3. **货币统一黑龙币**：所有金额（价格、退款、补偿上限）都用黑龙币，不再出现「元」。
